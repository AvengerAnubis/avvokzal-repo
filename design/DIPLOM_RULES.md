# Правила написания диплома

Данный файл содержит правила оформления и написания текста дипломной работы. AI-агент обязан следовать им при генерации любого контента.

---

## 1. Разметка заголовков

### 1.1. Уровни заголовков
- Основные заголовки разделов (1, 2, ВВЕДЕНИЕ, ВЫВОД, ЗАКЛЮЧЕНИЕ, СПИСОК ИСТОЧНИКОВ, ПРИЛОЖЕНИЕ и т.п.) помечаются как `[level1]`.
- Подзаголовки (1.1, 1.2, 2.3 и т.п.) помечаются как `[level2]`.
- Метка ставится **перед** текстом заголовка, без пробела.
- Пример: `[level1]ВВЕДЕНИЕ`, `[level2]1.1 Механика работы ИС`.

### 1.2. Пустые разделы
- Если раздел или подраздел не содержит текста (заполняется автором позже), после заголовка на следующей строке ставится `[void]`.
- Пример:
  ```
  [level1]ЭКОНОМИЧЕСКОЕ ОБОСНОВАНИЕ РАЗРАБОТКИ
  [void]
  ```

---

## 2. Списки

- Списки не нумеруются арабскими цифрами.
- Список начинается строкой `[list_start]` и заканчивается строкой `[list_end]`.
- Каждый элемент списка пишется с новой строки без нумерации и без маркеров.
- Пример:
  ```
  [list_start]
  Первый элемент списка;
  Второй элемент списка;
  Третий элемент списка.
  [list_end]
  ```

---

## 3. Пустые строки

- Между абзацами пустые строки **не ставятся** (отступы между абзацами настраиваются в MS Word).
- Пустые строки ДОПУСТИМЫ:
  - Перед `[list_start]` и после `[list_end]` для отделения списка от основного текста.
  - Перед `[листинг_X]` и после `[листинг_X_конец]`.
  - Перед `[рисунок_X]` и после `[рисунок_X]`.
  - Перед `[таблица_X]` и после `[таблица_X]`.
  - Между заголовками разного уровня (например, между `[level1]` и `[level2]`).

---

## 4. Язык и стиль

### 4.1. Запрещённые местоимения
- НЕ использовать местоимения первого лица: **я, мы, мой, наш, мне, нам, меня, нас** и их производные.
- Текст пишется в безличной или пассивной форме.

### 4.2. Запрет на «был / была / были / было»
- НЕ использовать формы глагола «быть» в прошедшем времени: **был, была, были, было**.
- ДОПУСТИМО: «разработано», «создано», «реализовано», «представлено» — без связки «было».
- Примеры:
  - НЕЛЬЗЯ: «Было разработано приложение...»
  - МОЖНО: «Разработано приложение...»

### 4.3. Научный стиль
- Текст пишется в строгом научном/академическом стиле.
- НЕ допустимы: художественные обороты, метафоры, эмоциональные оценки, разговорные выражения.
- Допустимы: факты, формулировки, определения, описания технических решений.

---

## 5. Объём

### 5.1. Подглавы
- Каждая подглава (например, 1.1, 1.2, 2.3) — **минимум 3 страницы** текста.

---

## 6. Листинги кода

### 6.1. Обязательное обращение
- Каждый листинг кода **должен быть упомянут в тексте** до его размещения.
- Формат обращения: `«... показан в листинге X»`, где X — порядковый номер листинга.
- Пример: «Код авторизации пользователя показан в листинге 1.»

### 6.2. Нумерация
- Листинги нумеруются сквозной нумерацией по всей работе: листинг 1, листинг 2, ...

### 6.3. Формат листинга
- Каждый листинг обрамляется метками `[листинг_X]` и `[листинг_X_конец]`, где X — порядковый номер.
- Пример:
  ```
  [листинг_1]
  function Hello({smth}: {smth: Number}){
    return smth + 1;
  }
  [листинг_1_конец]
  ```

### 6.4. Требования к коду в листингах
- НЕ включать большие фрагменты (целые классы — только если они небольшие).
- Предпочтительны отдельные методы/функции, выполняющие конкретную задачу.
- Листинги НЕ должны содержать комментариев.
- Код берётся из реального проекта, комментарии удаляются, пустые строки сжимаются.

---

## 7. Рисунки

### 7.1. Обязательное обращение
- Каждый рисунок **должен быть упомянут в тексте** до его размещения.
- Формат обращения: `«... показано на рисунке X»`, где X — порядковый номер рисунка.
- Пример: «Страница регистрации пользователя показана на рисунке 1.»

### 7.2. Нумерация
- Рисунки нумеруются сквозной нумерацией по всей работе: рисунок 1, рисунок 2, ...

---

## 8. Расположение элементов

### 8.1. Запрет на два одинаковых элемента подряд
- НЕЛЬЗЯ размещать два листинга кода подряд — между ними **минимум 3 строки текста**.
- НЕЛЬЗЯ размещать два рисунка подряд — между ними **минимум 3 строки текста**.
- НЕЛЬЗЯ размещать листинг и рисунок подряд — между ними **минимум 3 строки текста**.
- Между любыми двумя вставными элементами (листинг, рисунок, таблица) должно быть **не менее 3 строк связного текста**.

---

## 9. Список использованных источников

### 9.1. Формат источника
- Каждый источник оформляется по следующему шаблону:
  `Номер. Название — описание [Электронный ресурс]. — URL: https://... (дата обращения: ДД.ММ.ГГГГ);`
- Пример: `1. NextJS — документация фреймворка [Электронный ресурс]. — URL: https://nextjs.org/docs (дата обращения: 15.12.2024);`
- Источники нумеруются сквозной нумерацией: 1, 2, 3, ...
- Минимум 15, максимум 25 источников.

### 9.2. Ссылки на источники в тексте
- При упоминании технологии, фреймворка, стандарта или методологии необходимо ставить ссылку на соответствующий источник.
- Формат ссылки: `^[N]`, где N — порядковый номер источника.
- Ссылка ставится **сразу после** упоминания технологии, без пробела перед `^[`.
- Пример: «Фронтенд-часть реализована с использованием фреймворка NextJS^[11].»
- Пример: «Процесс аутентификации проектируется на основе JSON Web Tokens (JWT)^[7].»
- Если технология упоминается несколько раз в тексте, ссылка ставится при первом упоминании в каждом разделе.

### 9.3. Файл источников
- Список источников хранится в файле `SOURCES.md` в директории `design/`.
- Файл `SOURCES.md` обновляется при добавлении или изменении источников.

---

## 10. Чек-лист для AI-агента

Перед выдачей результата проверить:

- [ ] Заголовки размечены как `[level1]` / `[level2]`
- [ ] Пустые разделы содержат `[void]`
- [ ] Списки обёрнуты в `[list_start]` / `[list_end]`
- [ ] Между абзацами нет пустых строк
- [ ] Нет местоимений первого лица (я, мы, мой, наш...)
- [ ] Нет форм «был / была / были / было»
- [ ] Стиль — научный, без художественных элементов
- [ ] Каждая подглава содержит минимум 3 страницы текста
- [ ] Каждый листинг упомянут в тексте («листинг X»)
- [ ] Каждый рисунок упомянут в тексте («рисунок X»)
- [ ] Между любыми двумя вставными элементами — минимум 3 строки текста
- [ ] Все технологии и фреймворки имеют ссылки на источники в формате ^[N]
- [ ] Список источников содержит от 15 до 25 записей
- [ ] Каждый источник оформлен по шаблону с URL и датой обращения
